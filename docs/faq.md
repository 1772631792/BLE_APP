# 常见问题与排障

按现象查。先看设备页顶部的状态横幅和终端里的 `ERR` / `SYS` 日志，大部分问题那里已经写了原因。

---

## 1. 扫描不到设备

按可能性从高到低排查：

| 检查 | 说明 |
| --- | --- |
| 设备是否已上电、在广播 | 有些模块上电后要等几秒才开始广播；有配对键的长按进入广播 |
| 设备是不是被别人/别的 App 连着 | BLE 设备通常只允许一个连接，连上后多数会**停止广播**，此时谁也扫不到 |
| 上次是不是直接杀掉了 App | 旧连接可能还挂在设备端，设备以为自己在线 → 见下面第 2 条 |
| 权限是否给了 | Android 12+ 要「附近的设备」；Android 11 及以下还要定位权限 + 系统定位开关 |
| 蓝牙是否打开 | 点扫描会自动请求开启 |
| 是不是经典蓝牙设备 | 本 App 只支持 BLE（低功耗蓝牙），不支持经典蓝牙 SPP |

先试两件事：

1. 点「扫描」，等 12 秒（列表持续刷新）；
2. 扫不到就点列表上方的**「上次设备」卡片 → 连接**，它会绕过扫描直接连。

---

## 2. 重进 App 搜不到，必须给设备断电

**v3.0.1 已修复这个场景。**

原因：App 被系统杀掉（从最近任务划掉、后台回收）时不会执行 `dispose()`，断连包没发出去。Android 侧进程没了，但设备端如果没做断连检测，会一直以为自己还连着 → 停止广播 → 扫描必然为空。

现在的处理：

- 启动时先主动断开残留在同一台设备上的连接；
- 再按保存的 MAC 直连，完全不依赖扫描；
- 扫描 8 秒一个设备都没有时，也会自动直连一次兜底。

如果升级后仍偶发：

- 确认设备页「启动自动连接」是开的；
- 点「上次设备」卡片手动连一次；
- 仍然不行才需要给设备断电——那说明固件对断连的检测确实缺失，属于设备侧问题。

---

## 3. 启动没有自动连上

| 原因 | 处理 |
| --- | --- |
| 「启动自动连接」被关了 | 设备页打开它 |
| 打开 App 时蓝牙是关的 | 启动时不会主动弹窗请求开蓝牙，手动点一次「上次设备 → 连接」 |
| 设备不在范围 / 没上电 | 靠近设备后点「上次设备」卡片 |
| 只记住了最后一台 | 换设备要扫描后连接一次，才会更新记录 |
| 上次是主动点「断开」的 | 记录仍保留，下次启动照常尝试 |

自动连接失败会在终端留 `SYS` 日志，错误会弹 SnackBar。

---

## 4. 连上一会儿就断

- 距离 / 遮挡：BLE 在 2.4G 拥挤环境（Wi-Fi、微波炉）里会抖；
- 设备休眠：部分模块空闲几十秒就断开，需要 App 侧持续发数据；开启「心跳保活」（每 12 秒读一次特征值）；
- 设备只允许一个连接：别的手机连走了会把你顶掉；
- 断线后 App 会按 1→2→3→5→8→12→18→25 秒自动重连并恢复通知订阅，顶部横幅显示第几次尝试，可点「停止」。

---

## 5. 波形不出来

依次确认：

1. 数据页切到了「波形」；
2. 设备确实按 **VOFA+ JustFloat** 发：N 个小端 float32 + 帧尾 `00 00 80 7F`；
3. RX 特征值选对了，并且开启了通知（设备页「服务与特征值」）；
4. 终端里能看到 `RX` 行——看不到就是链路/通道问题，不是波形问题；
5. 帧尾对不对：`00 00 80 7F`，不是 `7F 80 00 00`。

> 波形只认 JustFloat，不支持 FireWater（文本）协议。

---

## 6. 控件按了没反应

| 原因 | 处理 |
| --- | --- |
| TX 特征值没选 | 设备页「服务与特征值」里把可写特征值设为 TX |
| 没连接 | 顶部横幅应显示「已连接」 |
| 发送模式选错 | 独立指令：每个控件各发一条；整包：按周期发合成包。固件只认其中一种 |
| 整包模板有未知占位符 | 终端会出现 `ERR`，检查模板里的 `{xxx}` 是否在白名单里 |
| 周期太长 | 整包默认 50 ms，改成 20 ms 更跟手 |
| 指令内容为空 | 控件设置里检查 payload |

---

## 7. 发送报错 / 数据发不出去

终端出现类似「超过单包上限」的 `ERR`：

- 单包上限 = `MTU - 3`，默认 MTU 23 时只有 **20 字节**；
- App 连上后会请求 MTU 517（上限 514），设备页顶部显示协商结果；
- 如果设备只支持小 MTU，需要精简整包模板（例如去掉包头包尾，或减少字段）；
- App 不做自动分包，这是为了避免破坏设备协议。

---

## 8. 设置丢了 / 换手机后要重配

- 指令、模板、周期、模式、各类开关都会自动保存在本机（`shared_preferences`），杀进程重开也在；
- 清除 App 数据、卸载重装会丢；
- 设置不跟随账号同步，换手机需要重新配。

---

## 9. 安装 / 升级

| 现象 | 原因 |
| --- | --- |
| 提示「应用未安装」 | versionCode 没有递增，或签名不一致 |
| 覆盖安装失败 | 先卸载旧版再装（会丢设置） |
| 提示未知来源 | 系统设置里允许该来源安装 |
| 安装后图标没变 | 用 `build.py` 打包才会同步图标 |

---

## 10. 权限相关

| 系统 | 需要什么 |
| --- | --- |
| Android 12+ | 「附近的设备」权限；**不需要定位权限**（已声明 `neverForLocation`） |
| Android 11 及以下 | 蓝牙权限 + 定位权限，且必须打开系统「位置信息」开关，否则扫不到 |
| 所有版本 | release 包不含 `INTERNET` 权限，App 不联网、无广告、无统计 |

---

## 11. 怎么把问题说清楚

反馈问题时带上：

1. 手机型号 + Android 版本；
2. App 版本（设置里/关于或安装包名里的 `vX.Y.Z`）；
3. 设备页顶部的状态（已连接 / 重连第几次 / MTU 值）；
4. 终端里相关的 `ERR` / `SYS` 行（右上角可复制全部）；
5. 是「扫不到」「连不上」「连上没数据」还是「控件没反应」——这四类的排查路径完全不同。
