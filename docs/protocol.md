# 协议与固件对接

给写固件的人看：App 会发什么字节、设备该怎么回、波形怎么编码。

App 侧有两套发送方式，在控件页的「控件设置」里切换：

| 模式 | 特点 | 适合 |
| --- | --- | --- |
| **独立指令**（默认） | 每个控件各发一条完整指令，互不干扰 | 收到一条执行一个动作 |
| **整包** | 摇杆 / 滑条 / 搓动 / 按键合成一个定长包，按周期发 | 按固定结构解析，抗丢包 |

---

## 1. 整包模式

### 1.1 默认模板（11 字节）

```text
AA 55 {x} {y} {s1} {s2} {tx} {ty} {btn} 55 AA
```

| 偏移 | 字段 | 类型 | 含义 | wire 编码 |
| --- | --- | --- | --- | --- |
| 0 | `0xAA` | 固定 | 包头 | — |
| 1 | `0x55` | 固定 | 包头 | — |
| 2 | `x` | int8 | 摇杆 X | `值 + 128`（0~255） |
| 3 | `y` | int8 | 摇杆 Y | `值 + 128` |
| 4 | `s1` | uint8 | 滑条 A | 原值 0~100 |
| 5 | `s2` | uint8 | 滑条 B | 原值 0~100 |
| 6 | `tx` | int8 | 搓动 X | `值 + 128`，**128 = 没搓** |
| 7 | `ty` | int8 | 搓动 Y | `值 + 128`，128 = 没搓 |
| 8 | `btn` | uint8 | 按键位图 | bit0~bit5 = k1~k6 |
| 9 | `0x55` | 固定 | 包尾 | — |
| 10 | `0xAA` | 固定 | 包尾 | — |

- 发送周期：20 / 50 / 100 / 200 ms 可选，默认 50 ms；
- 按键按下 / 松开、搓动变化会**立即补发一包**，不必等周期；
- 包长跟着模板走：模板改几个字段，就是几个字节。

### 1.2 固件解包

C：

```c
static void on_packet(const uint8_t *b, size_t len) {
    // 先卡包长，再验包头包尾，最后取值
    if (len != 11 || b[0] != 0xAA || b[1] != 0x55 || b[9] != 0x55 || b[10] != 0xAA) return;

    int8_t  x  = (int8_t)(b[2] - 128);   // -128 ~ 127
    int8_t  y  = (int8_t)(b[3] - 128);
    uint8_t s1 = b[4];                   // 0 ~ 100
    uint8_t s2 = b[5];
    int8_t  tx = (int8_t)(b[6] - 128);   // -128 ~ 127，0 = 没搓
    int8_t  ty = (int8_t)(b[7] - 128);
    uint8_t btn = b[8];
    bool k1 = btn & 0x01, k2 = btn & 0x02, k3 = btn & 0x04;
    bool k4 = btn & 0x08, k5 = btn & 0x10, k6 = btn & 0x20;
}
```

Python：

```python
import struct

def parse(frame: bytes):
    if len(frame) != 11 or frame[0] != 0xAA or frame[1] != 0x55:
        return None
    if frame[9] != 0x55 or frame[10] != 0xAA:
        return None
    x, y, tx, ty = struct.unpack('bbbb', bytes([frame[2], frame[3], frame[6], frame[7]]))
    return {
        "x": x, "y": y,
        "s1": frame[4], "s2": frame[5],
        "tx": tx, "ty": ty,
        "keys": [(frame[8] >> i) & 1 for i in range(6)],
    }
```

### 1.3 模板可以改

整包模板是纯文本，在「控件设置 → 整包模板」里直接改，改完自动保存：

```text
AA 55 {x} {y} {s1} {s2} {tx} {ty} {btn} 55 AA    默认，11 字节
AA 55 {x} {y} {s1} {s2} {btn} 55 AA              不要搓动，9 字节（v2 老模板）
{x} {y} {s1} {s2} {tx} {ty} {btn}                去掉包头尾，7 字节
{x} {y} {btn}                                    只要方向和按键，3 字节
```

**约束**：

- 支持的字面量是十六进制，字节间可用空格 / 逗号 / 分号 / 冒号；
- 占位符只能用白名单里的（见下表），写错会报「模板里有未知占位符」；
- 单包不能超过 `MTU - 3`：默认 MTU 23 → 20 字节，协商到 517 后最多 514 字节。

### 1.4 占位符

| 占位符 | 含义 | 范围 | HEX 里 |
| --- | --- | --- | --- |
| `{x}` `{y}` | 摇杆 | -128~127 | `值 + 128` |
| `{s1}` `{s2}` | 滑条 A / B | 0~100 | 原值 |
| `{tx}` `{ty}` | 右手搓动 | -128~127 | `值 + 128`，128 = 没搓 |
| `{btn}` | 按键位图 | 0~63 | bit0~bit5 |
| `{k1}`~`{k6}` | 单个按键 | 0 / 1 | 原值 |

关掉 HEX（文本模板）后，所有数值都是十进制字符串：`{x}` 直接是 `-128~127`，`{s1}` 是 `0~100`，按空格或逗号切分再转数字。

## 2. 独立指令模式

每个控件发自己的 payload，**没有统一包头**，靠内容区分：

| 控件 | 默认 HEX | 默认文本 | 识别方式 |
| --- | --- | --- | --- |
| 摇杆 | `AA 55 {x} {y} 55 AA` | `{x},{y}` | 6 字节，AA55 开头 55AA 结尾 |
| 滑条 A / B | `AA 55 {v} 55 AA` | `{v}` | 5 字节，中间 1 字节 0~100 |
| 右手搓动 | `AA 55 {tx} {ty} 55 AA` | `{tx},{ty}` | 6 字节，两轴 int8 |
| 按键 k1~k6 | 文本 `1`~`6` | 同左 | 内容自定，可改 HEX |
| 停止 | `S` | `S` | 一条普通文本 |

C 示例：

```c
// 摇杆 / 搓动：都是 6 字节，按指令内容区分是哪个控件
if (len == 6 && b[0] == 0xAA && b[1] == 0x55 && b[4] == 0x55 && b[5] == 0xAA) {
    int8_t a = (int8_t)(b[2] - 128);
    int8_t c = (int8_t)(b[3] - 128);
}

// 滑条：5 字节，中间就是 0~100
if (len == 5 && b[0] == 0xAA && b[1] == 0x55 && b[3] == 0x55 && b[4] == 0xAA) {
    uint8_t v = b[2];
}
```

每个控件的名称、内容、是否 HEX、是否开关式都能在「控件设置 → 指令列表」里改，改完自动保存。

## 3. 开关式按键

把某颗按键设成「开关式」后，它不再区分按下 / 松开，而是**每点一次发一次同样的指令**，固件收到就翻转：

```c
on_key5_packet() { relay_on = !relay_on; }
```

| 操作 | App 行为 |
| --- | --- |
| 第一次点 | 发一次该键指令，App 侧高亮 |
| 再点一次 | 再发一次同样的指令 |
| 长按 | 不进入连发（开关式没有按住的概念） |
| 松手 | 不发数据 |
| 整包模式 | 不单独发，`{btn}` 对应位保持 1，熄灭清 0 |

固件不需要知道状态，也不需要额外字段。

## 4. 波形：VOFA+ JustFloat

数据页「波形」只认 JustFloat：

```text
一帧 = N 个 IEEE-754 小端 float32 + 4 字节帧尾 00 00 80 7F
```

两通道，值 1.5 与 -2.25：

```text
00 00 C0 3F   00 00 10 C0   00 00 80 7F
└─ 1.5 ─────┘ └─ -2.25 ───┘ └─ 帧尾 ────┘
```

要点：

- **通道数 = 每帧 float 的个数**，不用预先声明；帧内多一个 float 就多一条曲线；
- 帧尾 `00 00 80 7F` 是 `+Inf` 的字节形式，正常数据不会出现，可安全当分隔符；
- 分包 / 粘包都能处理，跨 BLE 包的一帧会自动拼回来；
- 窗口保留最近 420 帧，超过 8 通道时颜色循环。

设备端 C 示例：

```c
float v[2] = {1.5f, -2.25f};
uint8_t frame[12];
memcpy(frame, v, 8);
const uint8_t tail[4] = {0x00, 0x00, 0x80, 0x7F};
memcpy(frame + 8, tail, 4);
ble_notify(frame, sizeof(frame));
```

Python 上位机模拟：

```python
import struct
payload = struct.pack('<ff', 1.5, -2.25) + b'\x00\x00\x80\x7f'
```

## 5. MTU 与分包

| 项 | 值 |
| --- | --- |
| 连接后请求 MTU | 517 |
| 实际单包上限 | `MTU - 3`（默认 23 → 20 字节，517 → 514 字节） |
| 超限行为 | 直接报错并在终端记 `ERR`，**不会自动拆包**（避免破坏设备协议） |

如果模板超过设备 MTU，先确认设备协商到的 MTU（设备页顶部会显示），要么精简模板，要么在固件侧约定分包。App 目前不做自动分包，这是有意为之。

---

## 6. 最小对接清单

1. 设备开一个可写特征值（App 设为 TX）和一个可通知特征值（App 设为 RX）；
2. 选一种模式：独立指令（简单）或整包（抗丢包）；
3. 固件按上面的字段表解析；`int8` 记得 `- 128`；
4. 要波形就按 JustFloat 发；
5. 协议变了不用改 App，在设置里改模板 / 指令即可。
